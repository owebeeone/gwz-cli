## 1. Findings

### [N-P3-1] R20's "once any lane has been made by one" understates the trigger: any write by a v2-aware binary upgrades the index

**Location.** `GwzLaneCleanFixes.md` R20:125-130 — "a v2-aware gwz reads v1 unchanged and **writes v2 on its first write**" versus "Every gwz binary used on one workspace must therefore be at or above the R20 release **once any lane has been made by one**"; the plan repeats the narrower trigger at section 1:146-149 ("once it holds an owned lane").

**Root cause.** The stated precondition is keyed to an *owned lane*, while the specified behaviour is keyed to *any index write* by a v2 binary.

**Violated invariant.** R20's own compatibility rule, which the operator will read as the condition under which an older binary is still safe.

**State sequence the text permits.** A workspace has never had a Claude lane and holds only hand-made rows. The operator runs one `gwz local dispose` (or `--keep`, or a family merge) with the R20 release. Per R20:126 the index is rewritten as v2. The operator, following the stated rule — no owned lane, so older binaries are fine — later runs the pinned 1.0.13 and finds the whole family index refused.

**Impact.** Bounded and self-diagnosing: the refusal names the minimum version (R20:127-128), and recovery is one install. But it is exactly the mixed-version surprise R20 was amended to prevent, in the one case the amendment's summary sentence excludes.

**Required correction.** Change both sentences to key on the write: *once any gwz at or above the R20 release has written the family index* — noting that a dispose or a `--keep` is such a write. Optionally state whether a v2 binary may be asked not to upgrade.

**Closure test.** R22's second test extended by one case: a v1 index written by a v2 binary performing a write that involves no owner at all comes back v2, and the v1-only decoder's refusal names the minimum version.

### [N-P3-2] The remove handler gets a wait but no timeout of its own, so a raised `--wait-secs` puts it past Claude's 600 s default

**Location.** D8:432-435 (dispose runs with `--wait <wait-secs>`, "the same deadline as the create hook"); D6:330-331 (compiled-in 300 s, "S1.0 revises it"); S1.2:604-607 sizes a timeout only for the **create** handler; section 1:69-70 (Claude's default command timeout is 600 s).

**State sequence the text permits.** S1.0 measures a long copy and raises `--wait-secs` above ~540 s (D6 explicitly anticipates the revision). Nothing is written, the directory still exists, so per section 1:61-63 the removal fails and the session is kept — fail-closed, which is why this is P3 — but the enumerated "family busy; retry" line, its log entry and its S4.1 table row never appear, and the operator sees a bare timeout instead of the class the patch created.

## 2. Invariant analysis

What survived a genuine attack on this revision and should not be re-litigated:

- **The concurrency story now closes end to end on the create side.** Two handlers, one `name`/`session_id`: the loser waits on its own session's `creating` row and reuses; who wins is irrelevant because both print the same path and exit zero. Two handlers, differing text, at the ceiling: one lane, no abort. A handler killed mid-copy: the sibling refuses fail-closed. A hung holder: refuse at the deadline, nothing created, the orphan named. A wait that outlives its deadline: the enumerated refusal row. I could not produce a state in which a wrong path is printed, a lane is deleted that `worktree_path` did not name, or a guard is bypassed by a reuse.
- **The decision is re-derived, never carried.** Every attempt re-reads the index lock-free (`read_view` genuinely takes no lock, `family-store-contract/src/lib.rs:283`) and cannot tear (atomic temp+rename, `family-store/src/lib.rs:6`). This is the structural reason the two round-4 P2s cannot recur in another dress.
- **Fail-closed is the default in every unowned direction**: no owner, foreign owner, foreign `creating`, `disposing`, path mismatch, incomplete lane, malformed token. The one loop in the table is keyed to the hook's own session and is bounded by a deadline.
- **The remove path's discipline is intact**: canonicalise first, resolve through `.gwz/family-root`, exactly one matching `ready` row, explicit `--root`, cwd at the family root (which `dispose.rs:202-206,226` genuinely needs — the containment check is lexical against the canonical cwd), never `--force`/`--keep`, absent path and vanished row both exit zero. Adding the wait did not weaken any of it.
- **Nothing sensitive escapes**: the log excludes `transcript_path` and `cwd`, is bounded and ignore-checked; the owner token stays in an ignored index and is redacted wherever the plan's own steps commit an inventory.
- **S1.4's ordering** remains the operator's stated choice with its consequence in the same paragraph; unchanged by this patch and adequate as framed.
- **Residual noted, not a finding:** a stale own-session `creating` row (from a timeout-killed earlier handler for the same session and name) makes the next attempt loop for the full deadline before refusing, rather than refusing at once. That is the price of not distinguishing a stale row from a live sibling without extra state — the alternative is exactly the sidecar this route deleted — and the outcome is fail-closed inside a timeout sized to cover it.
